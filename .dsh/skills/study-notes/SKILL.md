# 学习资料整理流程

角色和硬约束在 `AGENTS.md`，先按它执行。本文件讲整理一份材料的完整流程。

默认流程：**对话里出稿 → 用户确认 → 才写文件**，出稿时笔记和卡片一起给；用户说「直接归档」时才跳过确认。

## 0. 最容易做错的一件事

**怀疑老说法。** 材料里的结论在新版本还成立吗？很多「经典说法」只是上一个版本的实现细节。（查证要求见 `AGENTS.md` 的硬约束）

## 1. 判断是新主题还是已有主题

写文件前先读根 `INDEX.md` 和 `notes/` 现状。

- **已有主题** → 增量更新原文档，不要另起一篇内容重叠的新文档。
- **新主题** → 先定「领域 / 主题」两级路径，再决定单文件还是目录（见第 2 步）。

## 2. 拆分判定

**默认写单文件。** 内容多一点不是拆分理由——学习内容没变，组织方式合理有序就够了，一篇长文完全可以接受。

拆分的唯一判据：

> 能不能给这个主题写出一句「主干」？能，就写单文件。
> 只有主干之外还有**另外几条各自需要独立主干**的内容，且放在一起会让人分不清哪条是哪条时，才拆。

拆的时候：

- 按**可独立回忆的边界**拆，不按字数或卡片数平均切。
- 拆出来的每篇自己也要有完整的骨架：自己的「一句话」、自己的「打个比方」、自己的「主干」。
- 标题要能独立回答，不写「GMP（二）」这种离开上下文就没意义的标题。
- 片与片之间用相对链接互指，别让读者靠目录猜关系。
- 文件名用 ASCII slug，标题写中文。子主题继续长大时，对子主题递归套用同一套规则。

拆分后的结构：

```
notes/<领域>/<主题>/
├── 01-<子主题>.md
└── ...
```

## 3. 写正文

### 行文

- **语言**：中文为主，术语保留英文原词，首次出现写 `中文（English）`
- **结构**：先结论后展开；能用列表或表格就不写段落
- **密度**：一句话能说清就不写三行；长度随内容走，不凑字数
- **语气**：不写客套话，不写「总结一下」「接下来我们看」这类过渡

### 骨架

分两段：**先把理解和记忆建立起来，再提供校验和对照**。

**读**

1. **一句话** — 这是什么、解决什么问题
2. **打个比方** — 一个具体类比，把主干映射上去。读者靠它回忆起全文
3. **主干** — 不超过 3 条，每条给一个**钩子词**。忘了别的也要记得这三条
4. **展开** — 按主干顺序推：为什么成立、细节挂在哪。数字就写在它管的事情旁边

**查**

5. **反直觉** — 一律写成「你以为 X，其实 Y」
6. **和邻居的区别** — 用表格

没有内容的节可以省略，但不要改顺序。骨架是为记忆服务的，不是为了形式完整。**合格标准：读完能在 30 秒内复述出主干。**

### 容易写坏的地方

- **比方要能映射主干。** 每条主干都要能对上类比里的一个具体部件；映射不上的比方是坏比方，换一个，别硬圆。
- **钩子词要能直接出卡。** 主干每条给一个钩子词；如果连「X 指的是什么？」都问不出来，说明这条主干还没想清楚。
- **先讲问题，再给名词。** 如果读者得先背下几个名词才有资格理解「为什么需要它」，顺序就反了。
- **枚举按顺序或条件组织。** 状态、阶段、分支不要排成一张要硬背的表；按它经历的顺序，或按触发条件写。

### 版本基线

笔记里出现的源码行号、常量、运行时行为，必须在开头标注**基于哪个版本**核过（例：`Go 1.27.1`）。runtime、框架、协议这类跨版本变化明显的东西，老资料常有过时说法。

## 4. 制卡

卡片是**回忆的触发器**，不是笔记的摘要。**制卡是整理笔记的默认动作**——归档时笔记和卡片一起出，不用等用户开口要。

### 先选，再拆

两步顺序不能反：**选** —— 决定哪些内容值得考，决定**数量**，要克制；**拆** —— 把选中的内容拆成原子卡，决定**形态**，要细。

卡片是长期负债：每天新增 1 张，约换来每天 1 分钟复习量；一张卡的终身成本 2~5 分钟。

- **数量由内容里有多少核心点决定，不由笔记多长决定。** 能出卡的就三类：**主干**、**反直觉**、**关键数字**，以及它们之间的因果与机制。笔记正文里的细节、清单、源码标识符一律不出卡——需要时回笔记查。
- 出卡前先问：**这份内容里，哪些是「忘了就白学了」的？** 只给这些出卡。
- 觉得卡多时，回头砍**选题**，不要合并已经拆好的卡——那是把两个考点重新粘回一张卡。
- 粗卡不省事：知识点总数没变，写得粗只是让每张卡更难判分。**宁可漏，不可滥。**

### 选什么进制卡

优先级：**反直觉 / 关键数字 > 机制与因果 > 名词定义**。

- **主干三条各至少一张卡。** 主干是笔记唯一要求记住的东西，主干没卡等于没考。
- **只考已经查证的。** 查不实的宁可不做。
- **不机械拆分全文。** 叙述性、背景性、要靠整体理解的内容不做卡。
- **清单题不做。** 答案是一串名词的卡，背下来推不出别的。清单短、有结构、且高频用得上时才破例——破例时先给每个成员各出一张卡，再补一张排序卡。
- **源码标识符不进制卡。** 函数名、字段名、内部变量名（`runqputslow`、`sched.customGOMAXPROCS`）属于「查」不属于「背」。只有会出现在文档、报错、讨论里的名字（`GOMAXPROCS`、`runnext`）才单独考。
- **同一个考点可以有不止一张卡。** 同一事实的不同表征、不同方向、不同应用场景各出一张，对**重要**记忆是推荐做法。要消灭的不是重复，是**互相干扰**——两张卡长得像、答案都说得通、复习时想不起该答哪张。处理方式是改写或加一张**区分卡**，不是把两张粘成一张。

### 一张合格的卡

**一问一考点。** 遮住答案，问句只能指向**一个**事实。问句里有两个问号 → 一定是两张卡；答案里出现「和 / 以及 / ；」→ 通常也是。

**问句自足。** 不出现「它」「这个」「上面说的」，不依赖牌组里别的卡才能读懂。

**答案要能一秒判分。**

- 只写要回忆的那一小块，不写推导、解释或补充说明。本工作区取 **≤ 30 字、一行以内**作为近似标准（这是本工作区的约定，不是通行的行业标准）。写不下就是拆分信号，不是排版问题。
- 遮住答案自己答一遍：**超过 10 秒还想不起来，或答完不知道算对算错，这张卡就要改。**
- **不能由问句推出来**，也不写「因为……所以……」——推得出来等于没考，要考因果就单独问「为什么」。
- 数字单独考就单独成卡：「256」「61 轮」「129 个」——数字最好考，也最容易互相污染，一卡一个。

**考结论，不考是/否。** 「X 是不是 Y」有 50% 蒙对率，改写成「X 是什么 / X 限制了什么 / 什么时候会 X」。用开放式疑问词（什么 / 多少 / 多大 / 几 / 为什么 / 怎么 / 什么时候），去掉「是不是 / 有没有 / 对不对」和「请」「下面」「上述」这类填充词。`<code>` 只包最小片段（`<code>GOMAXPROCS</code>`），不要把整句包进代码标签。

### 什么时候用 cloze

默认用问答对（Basic）：遮住答案逼出完整回忆，理解更深。cloze 更省力，也更容易退化——复习几轮后你可能只是在补全句子，而不是在回忆。以下情况才用 cloze：

- 有序序列、诗句、图上成分 → cloze 或 image occlusion。
- **一次只挖一个语义槽**；一句话要挖两处，就出两张卡。
- 怎么都拆不出原子卡时，cloze 是省力的兜底——先挖出来，比硬憋一张大问答卡强。

### 难卡（leech）怎么处理

反复「忘记」的卡不要硬啃，它是诊断信号：

- **先找缺失的基础卡。** 难卡常常是缺一张前置卡；补上之后它自己就变简单了。
- **同义词互扰** 就再加一张**区分卡**，把两者的差别写清楚。
- **不核心就删。** 难卡占用的复习时间是普通卡的好几倍。

### 坏卡 → 好卡

| 坏 | 病 | 好 |
|---|---|---|
| GMP 里 P 的三个身份是什么？ | 一卡三考点 | 三张卡：M 执行 Go 代码的前提？→ 持有 P ／ 每个 P 自带什么，让分配小对象不必抢全局锁？→ mcache ／ 什么限制了「同时执行 Go 代码」的数量？→ P 的数量 |
| 手动调用过 runtime.GOMAXPROCS 之后，自动调整还会生效吗？ | 是非题，答案还塞了源码字段名 | 什么时候 Go 会停止自动调整 GOMAXPROCS？→ 用户手动调用过 runtime.GOMAXPROCS 之后 |
| sysmon 有哪几项职责？ | 清单题 | 删掉，或只考最反直觉的一项 |
| 一个主题出了 59 张卡，逐段覆盖笔记 | 把「查」的内容也做成了卡，数量失控 | 先选再拆：只留主干 + 反直觉 + 关键数字，其余留在笔记里 |

> 表里的「→」只为在这里排版；写进 `.tsv` 时问句和答案之间是 **Tab**。

出卡后拿上面两节过一遍：**任何一条不过，就改或删。**

文件格式（Anki 2.1.54+ 文本导入头）：

```
#separator:Tab
#html:true
#notetype column:1
#tags:<领域>::<主题>
#deck:<领域>
问答题	前端问题	后端答案
填空题	一句话，把要遮住的部分写成 {{c1::这样}}
```

- 命名 `anki/<领域>-<主题>.tsv`；主题拆成目录时，才按子主题拆成多个文件。
- **第一列是用户收藏里的笔记类型名，必须逐字一致。** 本工作区所在收藏是中文界面建的，实际叫 `问答题` / `填空题`（已核过该收藏的 `notetypes` 表）；换收藏或换语言要重新核。写成收藏里不存在的名字（`Basic` / `Cloze`），Anki **不会**自动新建，那一行直接按「缺少其笔记类型」跳过，导入后一条不剩。
- `#notetype column:1` 是 Anki 2.1.54+ 的特性：声明后同一文件里能混用两种卡型。这一列不参与字段映射，剩下的列按顺序分给各 note type 的字段（问答：正面／背面；填空：文字／背面额外，留空即可）。判重仍看第一个**普通列**（这里就是问句那列），所以混用不影响重新导入时的原地更新。
- 字段之间用 **Tab** 分隔，字段内不能出现 Tab；换行用 `<br>`，代码用 `<code>`，缩进用 `&nbsp;`。**出现 `<br>` 基本等于这张卡该拆。**
- **牌组只到领域一级。** 按主题细分牌组会让卡片按可辨认的顺序出现，复习时能凭上下文猜出答案，记忆反而更弱（Anki 官方明确不建议）。主题用 `#tags:` 区分——tag 还能一卡多个，牌组不行。
- cloze 正文写 `{{c1::要遮住的部分}}`：同一个编号 → 一张卡，不同编号 → 多张卡。**遮整段序列，别遮单个词**——只遮一个词会退化成补句子，句子里剩下的词成了免费提示。

## 5. 更新索引

每次归档后更新根 `INDEX.md` 的「主题索引」表：

| 情况 | 动作 |
|---|---|
| 新增主题 | 加一行 |
| 主题拆分 | 原行换成目录链接，更新笔记篇数与卡片数 |
| 不再维护 | 删掉该行 |

## 6. 收尾报告

向用户报告：

- 实际写了哪些文件（完整路径）
- 卡片数
- 为满足第 4 步标准**删掉了哪些卡**（清单题、查不实、互相干扰）
- 核实过程中发现材料里的哪些过时或错误说法
- 不主动安排复习计划
